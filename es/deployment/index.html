Informe técnico de desarrollo | Osnias Clearing

Osnias Clearing desarrolla una infraestructura europea de compensación multilateral de obligaciones comerciales B2B. Las misiones realizadas han constituido una base de software documentada: núcleo EVM portable, registros de identidad y nodos, gobernanza de cámaras, interfaces de gestión e interoperabilidad ISO 20022 y EBICS. El próximo hito es un piloto integrado reproducible.

01 / 11

Síntesis general

El desarrollo ha superado la documentación conceptual. El repositorio privado de desarrollo contiene contratos Solidity, servicios Go, interfaces TypeScript, bibliotecas XML y adaptadores bancarios, con pruebas automatizadas, campañas de integración e informes de recepción.

Estas realizaciones cubren una parte importante de la infraestructura. Sin embargo, el motor Go de compensación, el registro operativo de obligaciones y el proceso completo de liquidación siguen pendientes de desarrollo o cualificación. El número de pruebas superadas no determina por sí solo la madurez global del protocolo.

02 / 11

Arquitectura de software

La arquitectura separa cuatro conjuntos: aplicaciones para empresas y ERP, cálculo fuera de cadena en Go, registro distribuido Solidity/EVM y adaptadores bancarios. El cálculo de compensación no se ejecutará en el núcleo Solidity: el motor Go calculará las posiciones netas y sus resultados se registrarán en EVM.

El núcleo utiliza Solidity estándar, portable entre redes compatibles con EVM. Sei es la red de referencia, no una dependencia obligatoria del núcleo. Las adaptaciones de red, conectores ERP y pasarelas bancarias permanecen separados. El diagrama describe la arquitectura objetivo y no una integración ya terminada.

03 / 11

Núcleo Solidity / EVM

Los oráculos temporales organizan los ciclos 1W, 9W y 13W. Los registros Osnias-ID y V2 relacionan identificadores con direcciones EVM y comprueban estados, formatos e integridad. Los contadores locales por nodo asignan identificadores secuenciales con límite de 9.999.999, sin reutilización.

Los contratos de cámaras relacionan divisa, ciclo y nodo. La gobernanza bilateral separa autoridades y rechaza acciones no autorizadas. M38-4 documenta 252 pruebas Foundry superadas de 252 y escenarios de integración Anvil. Faltan integrar el registro completo de obligaciones y las certificaciones de firmeza.

04 / 11

Node Manager y Protocol Manager

Node Manager es una aplicación TypeScript para administrar nodos: autenticación mediante cartera, consulta de registros, vistas de cámaras, controles de gestores autorizados y aislamiento de ámbitos. Protocol Manager presenta vistas administrativas y operaciones controladas de gobernanza.

Ambas aplicaciones disponen de pruebas unitarias y escenarios de integración EVM local. Son demostradores técnicos: incorporación de empresas, procesos ERP y explotación multinodo real requieren desarrollo y cualificación.

05 / 11

Interoperabilidad ISO 20022

La capa Go ISO 20022 incluye un catálogo de 30 versiones de esquemas, mecanismos de lectura y validación XML, controles XSD, datos de prueba y herramientas de cualificación. Busca intercambiar mensajes financieros con los bancos de forma independiente del núcleo EVM.

M14 señala dos incidencias bloqueantes: ciertos recorridos no demuestran que se haya ejecutado realmente la validación XSD, y algunos validadores personalizados no controlan completamente los plazos. Se requieren corrección y nueva cualificación antes de afirmar una conformidad global.

06 / 11

Conector bancario EBICS 3.0 H005

El conector bancario Go ha avanzado en diez etapas, M39-T01 a T10: esquemas XSD H005, análisis de diferencias, raíces XML, cabeceras, mensajes INI/HIA, especificación XMLDSig, módulo de firmas Go, integración AuthSignature, FUL/FDL en dos fases y solicitudes HPB corregidas.

T10 documenta 49 pruebas Go EBICS y 20 XMLDSig superadas, capturas válidas según XSD, firmas verificadas con xmlsec1 y escenarios negativos de alteración. También constan comprobaciones build, vet y race. Las respuestas de claves, la semántica S002/A006 y las pruebas con un banco independiente requieren cualificación.

07 / 11

Depósitos y oráculo bancario

La arquitectura prevé cuentas individualizadas por Osnias-ID, divisa y ciclo, con seguimiento de saldos, bloqueos, débitos, créditos y fondos inmovilizados. El oráculo bancario independiente deberá devolver esta información sin depender del registro distribuido.

El repositorio contiene estructuras de certificación, módulos Go y simuladores. El depósito en EVM puede ser una alternativa seleccionada por el cliente, no una dependencia del núcleo. No se ha cualificado una conexión bancaria real ni una certificación de cuenta real.

08 / 11

Madurez de los componentes

Los componentes con pruebas más avanzadas son los registros EVM, la gobernanza de cámaras, los oráculos temporales y el conector EBICS H005. Node Manager y Protocol Manager siguen siendo demostradores locales. ISO 20022 cuenta con una biblioteca sustancial pero mantiene reservas de cualificación.

Quedan por entregar o integrar el registro de obligaciones comerciales admisibles, el motor Go multilateral, las API ERP y un ciclo completo de compensación con confirmación bancaria. Cada componente debe evaluarse de manera independiente.

09 / 11

Desarrollos pendientes

La primera etapa consiste en crear un registro operativo de obligaciones: admisión, aceptación, estados, validez y firmeza. La segunda es el motor Go de compensación multilateral, con cálculo reproducible, reglas de rechazo y control de posiciones netas.

Después se publicarán resultados en EVM, se conectarán las interfaces ERP, se corregirán las incidencias ISO 20022, se cualificará EBICS con un banco independiente y se ejecutarán ciclos completos con pruebas de carga, seguridad, supervisión y recuperación.

10 / 11

Cualificación, seguridad y riesgos

La cualificación debe cubrir la coherencia comercial de las obligaciones admitidas, la interoperabilidad ERP–Go–EVM–banco, la seguridad de claves y firmas, la separación de permisos y la gestión de incidentes. Las pruebas unitarias no sustituyen los escenarios entre componentes.

Los resultados proceden de campañas internas documentadas. No constituyen certificación bancaria, auditoría independiente finalizada, aprobación regulatoria ni autorización de despliegue en producción.

11 / 11

Conclusión técnica

Osnias Clearing dispone de una base de software sustancial: contratos Solidity/EVM, registros, gobernanza, oráculos, interfaces TypeScript, servicios ISO 20022 y un conector EBICS H005. Las misiones han convertido especificaciones de arquitectura en componentes verificables y comprobables.

El próximo hito decisivo será demostrar un ciclo completo: obligación B2B admitida, compensación multilateral fuera de cadena, posiciones netas registradas en EVM y confirmación bancaria en pruebas. Esta integración permitirá una evaluación sólida por proveedores ERP, bancos y socios institucionales.
