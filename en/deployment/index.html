Technical progress · 5 November 2026

From architecture to an integrated demonstrator

A substantial codebase developed and tested. The private development repository contains the portable Solidity/EVM core, identity and node registries, chamber governance, Node Manager and Protocol Manager interfaces, ISO 20022 libraries and a Go-based EBICS 3.0 H005 connector. Sei remains the reference network without imposing a dependency on the core.

1. EVM core, identity and governance

The 1W, 9W and 13W temporal oracles, Osnias-ID and node V2 registries, sequential identifier counters, chamber associations and bilateral governance controls have Solidity implementations. The M38-4 campaign reports 252 of 252 Foundry tests passed and integration scenarios executed on Anvil, a local test network.

2. Node Manager and Protocol Manager interfaces

The TypeScript node and protocol management interfaces include wallet-based authentication, authorisation checks, chamber views and locally tested governance workflows. They remain demonstrators rather than live clearing services.

3. ISO 20022 and banking interoperability

The ISO 20022 catalogue covers 30 schema versions, with Go components, XSD validation and test fixtures. The M14 cross-functional qualification still identifies two blocking issues relating to proof of actual validation and enforcement of timeouts. They require correction and requalification.

The Go EBICS 3.0 H005 banking connector has completed stages T01 to T10: official schemas, INI/HIA envelopes, XMLDSig authentication, two-phase FUL/FDL transfers and a corrected HPB request. The T10 report records 49 Go and 20 XMLDSig tests passed, alongside XSD conformance checks and xmlsec1 signature verification. Key-management responses, the semantic S002/A006 order-signature format and interoperability with an independent bank server remain to be qualified.

4. Next milestone: a complete pilot cycle

Outstanding work includes an operational trade-obligation registry, the off-chain Go multilateral netting engine, publication of net positions to EVM, ERP APIs and qualification of bank connectivity. The aim is a reproducible end-to-end pilot cycle before any operational deployment.

1. Public registry of testnet deployments

This page is the public reference for the Osnias Clearing smart contracts currently deployed on testnets. It lists the addresses, creation transactions, compilers, verification parameters and status of each component so that the experimental state of the infrastructure can be verified directly on chain explorers.

2. Sei layer — canonical ledger and clearing control

The Sei Testnet Atlantic-2 layer brings together the temporal oracle, the identity registry and the protocol controller. These components represent the clearing side of the architecture: canonical state, cycle control, identity and clearing positions, without constituting a production Mainnet environment.

3. EVM layer — nodes, registry and escrow

The Ethereum Sepolia layer brings together the EVM components associated with node operators: Node Registrar, EVM registry, escrow contract and EVM controller. This separation makes it possible to test publicly the interaction between the clearing ledger on Sei and the external escrow and EVM control layer before any production deployment.

4. Verifiable testnet infrastructure and public smart contract registry

The Deployment page is the public reference for Osnias Clearing smart contracts deployed on accessible testnets. It centralises contract addresses, creation transactions, compiler versions, optimisation parameters and verification status in order to provide a public smart contract registry usable by developers, auditors and technical partners.

The testnet architecture is split between Sei Atlantic-2, which carries the canonical clearing ledger, the temporal oracle and the protocol controllers, and Ethereum Sepolia, which hosts the EVM components associated with nodes, the local registry and escrow. This separation makes it possible to test an on-chain clearing infrastructure publicly without conflating the clearing layer with collateral, custody or settlement functions.

The deployments presented are experimental and do not constitute production Mainnet infrastructure. Their role is to provide verifiable references on SeiScan and Etherscan, to enable validation of the smart contracts and cross-domain interfaces, and to document the technical state of the protocol before any migration to auditable production infrastructure.

Osnias Clearing Desk

An Osnias Clearing end-user application is currently available online on Sei Atlantic-2 Testnet. It shows the state of the ledger, the clearing cycle and the temporal oracle from an operational demonstration interface.

  • Display of the cycle, the clearing windows and the oracle state.
  • Test interfaces for instructions, transfers and registry.

This interface is a demonstration environment under development. It runs on testnet only and is not a production service.
