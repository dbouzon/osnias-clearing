Technical development report | Osnias Clearing

Osnias Clearing is developing a European multilateral netting infrastructure for B2B trade obligations. Completed missions have established a documented software foundation: portable EVM core, identity and node registries, chamber governance, management interfaces and ISO 20022 and EBICS interoperability. The next milestone is a reproducible integrated pilot.

01 / 11

Executive overview

Development has progressed beyond conceptual documentation. Solidity contracts, Go services, TypeScript interfaces, XML libraries and banking adapters are present in the private development repository, with automated tests, integration campaigns and acceptance reports.

These accomplishments represent a substantial part of the infrastructure. However, the Go netting engine, operational trade-obligation registry and complete settlement pathway remain to be implemented or qualified. Passing test counts alone cannot establish overall protocol readiness.

02 / 11

Software architecture

The architecture separates four domains: corporate and ERP applications, off-chain Go calculations, the distributed Solidity/EVM registry and banking adapters. Business netting calculations do not run inside the Solidity core: the Go engine is intended to compute net positions, whose results are then recorded on EVM.

The core uses standard Solidity and remains portable across EVM-compatible networks. Sei is the reference deployment, not a mandatory core dependency. Network adaptations, ERP connectors and banking gateways remain external. The diagram describes the target architecture, not an already completed end-to-end integration.

03 / 11

Solidity / EVM core

Temporal oracles organise the 1W, 9W and 13W cycles. Osnias-ID and V2 registries associate identifiers with EVM addresses and check statuses, structure and integrity. Node-local counters assign sequential IDs up to 9,999,999 without recycling.

Chamber contracts associate currency, cycle and node data. Bilateral governance separates authorities and rejects unauthorised actions. M38-4 reports 252 out of 252 passing Foundry tests with Anvil integration scenarios. A complete obligation registry and finality attestation remain to be integrated.

04 / 11

Node Manager and Protocol Manager

Node Manager is a TypeScript node-administration application covering wallet authentication, registry readings, chamber views, authorised-manager checks and isolation among node scopes. Protocol Manager offers administrative views and controlled protocol-governance operations.

Both applications have unit tests and local EVM integration scenarios. They are technical demonstrators: company onboarding, ERP workflows and real-world multi-node operation still require development and qualification.

05 / 11

ISO 20022 interoperability

The Go ISO 20022 layer includes a catalogue of 30 schema versions, XML reading and validation mechanisms, XSD checks, test fixtures and qualification tools. It is intended to exchange financial messages with banks independently of the EVM core.

M14 reports two blocking findings: some paths do not prove that XSD validation actually ran, and some custom validators do not fully enforce execution time limits. These issues must be corrected and requalified before claiming global conformance.

06 / 11

EBICS 3.0 H005 banking connector

The Go banking connector has progressed through ten stages, M39-T01 to T10: H005 XSD references, gap analysis, XML roots, headers, INI/HIA messages, XMLDSig specification, Go signature module, AuthSignature integration, two-phase FUL/FDL and corrected HPB requests.

T10 documents 49 passing Go EBICS tests and 20 XMLDSig tests, XSD-valid captures, xmlsec1 signature verification and negative tampering scenarios. Build, vet and race checks are also reported. Key-management responses, S002/A006 semantics and independent-bank server interoperability still need qualification.

07 / 11

Bank escrow and oracle

The target architecture provides dedicated escrow accounts for each Osnias-ID, currency and cycle, monitoring balances, locks, debits, credits and blocked exposure. The independent bank oracle should return this information without relying on the distributed ledger.

Attestation structures, Go modules and simulators are present. EVM escrow may be an alternative selected by the customer rather than a mandatory core dependency. No real bank connection or real escrow account attestation has yet been qualified.

08 / 11

Component maturity

The most extensively tested components are EVM registries, chamber governance, temporal oracles and the EBICS H005 connector. Node Manager and Protocol Manager remain local demonstrators. ISO 20022 has a substantial library but documented qualification reservations.

Key components still to deliver or integrate include an admissible trade-obligation registry, the multilateral Go netting engine, ERP APIs and a full clearing sequence with bank confirmation. Each component must be assessed separately.

09 / 11

Remaining development work

First, build an operational trade-obligation registry covering admission, acceptance, state transitions, validity and finality. Second, build the Go multilateral engine with reproducible calculations, rejection rules and net-position controls.

Then publish results on EVM, connect ERP interfaces, resolve ISO 20022 findings, qualify EBICS with an independent bank and execute full cycles with load, security, monitoring and recovery tests.

10 / 11

Qualification, security and risks

Qualification must address the integrity of admitted obligations, ERP–Go–EVM–bank interoperability, key and signature security, role separation and incident management. Unit tests cannot substitute for cross-component scenarios.

Results are drawn from documented internal test campaigns. They are not banking certification, a completed independent audit, regulatory approval or an authorisation for production deployment.

11 / 11

Technical conclusion

Osnias Clearing now has a substantial software foundation: Solidity/EVM contracts, registries, governance, temporal oracles, TypeScript interfaces, ISO 20022 services and an EBICS H005 connector. Successive missions have turned architectural specifications into verifiable and testable components.

The decisive next milestone is a full pilot cycle: admitted B2B obligation, off-chain multilateral netting, net positions recorded on EVM and bank confirmation in a test environment. Such integration will support credible evaluation by ERP vendors, banks and institutional partners.
