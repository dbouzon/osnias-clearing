Mistral executes · OpenAI reviews · GitHub is the record of truth

COORD separates execution, independent review, durable evidence and human authorization. Mistral and OpenAI are examples of interchangeable agents, not protocol dependencies.

01 · Roles

Four strictly separated roles

Role separation is the core invariant of the protocol: execution, review, registry and steering are never given to the same actor.

EXECUTOR

Mistral

Designs, executes and publishes: code, tests, execution proofs, reports. Can never issue a verdict on its own work.

REVIEWER

OpenAI (API)

Reviews the plans and receives the deliverables. Issues a verdict anchored to the exact Git SHA: ACCEPTEE, A_CORRIGER or REFUSEE. Never a self-review.

REGISTRY / PILOT

GitHub · human

Issues, PRs and comments are the public record of truth. Closing, merging and activating versions remain reserved to the human pilot.

02 · State machine

One mission, controlled transitions

Each mission moves through an explicit v1.0 state machine, valid in any language:

OUVERTE → PLAN_CRITIQUE → EN_EXECUTION → RECEPTION_DEMANDEE → DECISION_API → (A_CORRIGER → EN_EXECUTION) → ACK_MISTRAL → CLOTURE

A verdict is anchored to the pair (exact Git SHA, fingerprint of the proofs): if either changes, the verdict is stale and the review must be replayed. Publications are idempotent: a duplicate is never re-processed.

03 · A real, end-to-end mission

Lived example: mission M-COORD-09

The mission that produced version v1.4 is also the protocol's most demanding E2E test, stricter than any simulated test.

Real sequence: version inventory and diagnosis → v1.4 specification → OpenAI prior review (a real A_CORRIGER, then the plan accepted after correction) → execution: module, 17-test battery, launcher → independent review on the exact SHA → consolidated reports. Session interruptions and environment lock-downs documented and resumed through the resume state, with no fictitious verdict.

05 · Implement the protocol in your project

Few rules, any language

The protocol fits on one page: minimal states and transitions, a recording format, comment conventions and a few non-negotiable invariants.

A mission record is one normalised JSON line: mission, issue, state, protocol, sha_git, proof_fp (sha256 fingerprint of the proofs), model_api, ts_utc, verdict_url, verdict_id, ack. Asynchronous exchanges use marked comments: FROM:MISTRAL, FROM:CHATGPT-API DECISION and TO:MISTRAL.

Invariants to reproduce: mandatory independent review · never a self-review · never a PASS without real execution · verdict staling by fingerprint · idempotent publications · no secrets in repositories.

The full specification (proto-coord06-v14, in French) is public, and the open standard COORD Specification 1.0 is implemented by a Go reference engine (coord/go, stdlib only). The historical infrastructure tools/ai-coordinator remains published for the record (documented divergence).

06 · COORD Specification 1.0

The open standard, language-neutral

COORD Specification 1.0 formalises the protocol as a self-contained normative specification (English, RFC 2119), implemented by two independent reference engines.

STANDARD

Specification 1.0

Eight states, a closed transition table, fail-closed authorizations, referenced verdicts, staling by fingerprint, atomic persistence, resume arbitration, context control (invariants N-01..N-20). Read the standard.

GO ENGINE

Stdlib reference

The coordengine module (Go 1.27, zero dependency), an autonomous demo and a vector runner. 22/22 vectors and 19 conformance checks, verified by CI on Linux, Windows and macOS.

CONFORMANCE

22 public vectors

Three positive transition scenarios, nine negative ones, eight authorization configurations, two resume arbitrations. An implementation is conformant when it replays all of them. Answer the call for implementations.

Public deliverables: standard (coord/docs/spec/coord-spec-1.0.md) · 5 JSON schemas 2020-12 (coord/schemas/) · vectors (coord/docs/conformite-v15/) · implementer guide (EN) · user guide (FR) · replay: go run ./cmd/vector-runner -dir ../docs/conformite-v15 and go run ./cmd/coord-demo. 07 · Status and limits

What is proven, what is not

Transparency about limits is part of the protocol: every claim distinguishes what was executed from what was not.

Status: v1.4 operational (reference). Non-activated candidates: hardened v1.5 and COORD Specification 1.0 with its Go reference engine; activation remains reserved to the human pilot. Limits: UNIT/MOCK batteries, no simulated E2E is presented as real; Go multi-OS qualification and schema validation executed by CI; the software is licensed under Apache-2.0; a French version of this page is the reference version, Spanish not included.
Architecture · Research

Inter-agent communication stack

A conceptual stack inspired by ISO/OSI, not a standardized OSI mapping. COORD governs, A2A structures exchanges, MCP encapsulates them in the proposed experiment.

Example: COORD authorizes a task, the A2A message carries its identity and content, an experimental MCP gateway forwards it to an agent and returns the result. COORD retains authority over acceptance. MCP is not TCP and does not natively guarantee A2A interoperability.

Research question: compare direct A2A with encapsulated A2A using simulated agents, measuring fidelity, latency, traffic, recovery and security. No performance benefit or Gemini compatibility is claimed yet. #38 · A2A · MCP

Reference software and evidence

Python reference and Go engine; Pilot and orchestration; provider connectors; read-only MCP server reviewed in PR #37. The experimental gateway is separate from the read-only server. Go · SEC-01 · MCP #37.
