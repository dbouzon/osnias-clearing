Technical roadmap · October 2026

From the existing foundation to the security audit

13 building blocks · 4 work packages · Multi-node demonstrator · Independent audit

Osnias Clearing is not starting from scratch. A reference architecture, the L1–L7 technical corpus, testnet deployments on Sei and Ethereum Sepolia, regulatory pre-assessment work and initial exchanges with the ecosystem already form the project’s foundation.

The next phase covers integration, testing, industrialisation, a multi-node demonstrator, security hardening and an independent audit. It is broken down into building blocks B0 to B12, grouped into four work packages, each of which delivers a demonstrable output and prepares the next.

03 · Building blocks

B0 to B12: what is available and what remains

Each block is described by what has already been achieved and by what remains to be integrated, tested or developed.

Package 1

Core Protocol

B0Completed

Reference architecture

Available
  • Separation of clearing / settlement / custody functions.
  • Canonical clearing ledger and its interface with the EVM layer.
  • Netting cycles, operating rules and main invariants.
  • Core built on standard EVM primitives, network dependencies confined to adapters; Sei remains the reference deployment, local O-POPs remain standardised and replicable.
To do
  • Freeze a versioned technical baseline for integrated development and the audit scope.
B1To industrialise

Core Clearing Engine

Available
  • Calculation of net positions and netting cycles.
  • MINT / BURN / CLEAR states, snapshots and freeze rules.
  • Global position-consistency invariant.
To do
  • Assemble an integrated, reproducible reference engine.
  • Automate unit tests and multi-participant simulations.
  • Document and test edge cases and error scenarios.
B2Testnet

Canonical DLT ledger — Sei reference

Available
  • Deployments and experiments on Sei Testnet.
  • Time oracle and consolidation of liabilities / positions.
  • Ledger of clearing operations.
To do
  • Full integration with the clearing engine.
  • Recovery, replayability, failure, load and write-consistency testing.
  • Formalise contract interfaces and events.
  • Isolate Sei dependencies in a dedicated adapter, enabling future EVM migration or multi-deployment without rewriting the core.
B3Testnet

EVM settlement & collateral

Available
  • EVM escrow and controller deployed on Sepolia.
  • Testnet collateral, solvency checks, controlled mint / burn.
To do
  • Integrate the EVM layer with the canonical clearing ledger.
  • Strengthen Foundry tests, fuzzing and solvency invariants.
  • Test adversarial behaviour, errors and recovery procedures.
B4Prototyped

Osnias-ID

Available
  • Osnias-ID format, network / node identification, checksum, anti-collision rules.
  • Associated registry and fail-closed behaviour.
To do
  • Integrate Osnias-ID across all components and messages.
  • Test collisions, checksum, multi-network and fail-closed scenarios.
Package 2

Infrastructure & Interoperability

B5Partial

Time & solvency oracles

Available
  • Cycle time oracle on the clearing layer.
  • Solvency oracle for network collateral control.
To do
  • Define redundancy, thresholds and failure policy.
  • Test unavailability, delay, outlier values, freeze and recovery.
B6To develop

ISO 20022 interoperability

Available
  • Functional architecture and interface requirements with nodes and settlement systems identified.
To do
  • Mapping of Osnias events ↔ ISO 20022 messages.
  • Orders, confirmations, statuses and error handling.
  • End-to-end simulated settlement scenarios.
B7To develop

Jurisdictional O-POPs & nodes

Available
  • O-POP topology by KK zone and KK-NNN nodes.
  • Private RPC, VPN tunnels, logging and monitoring.
  • Replicable O-POPs connected to the same core, operable according to local requirements.
To do
  • Deploy a first pilot O-POP and a reproducible package: configuration, network plan, hardening, monitoring, documentation, acceptance testing.
  • Test network security, connection loss, latency, recovery and service continuity.
Package 3

Integrated Demonstrator

B8To integrate

Cross-layer reconciliation

Available
  • Post-Clearing Mirror Reconciliation principle documented.
  • Consistency invariant between post-clearing positions and eligible assets / collateral.
To do
  • Automate divergence detection, proofs, logs and corrective procedures.
  • Test desynchronisation and controlled recovery.
B9To develop

Security hardening

To do
  • Static analysis and dependency review.
  • Foundry, fuzzing and invariant testing.
  • Access controls, adversarial scenarios, economic attacks and DoS.
  • Review of the threat model and operating procedures.
  • Exit criterion: no known critical vulnerability before handover to the auditor.
B10To develop

Integrated testnet demonstrator

To do
  • Full demonstrator: simulated participants, several nodes, multilateral clearing, DLT ledger, collateral, settlement, Osnias-ID, oracles and reconciliation.
  • Several complete cycles, nominal and failure scenarios.
  • Evidence, logs, metrics and reproducible documentation.
Package 4

Security Audit

B11To audit

Audit readiness

To do
  • Code freeze and reference version.
  • Final architecture, specifications, threat model, list of invariants.
  • Test dossier, coverage, contract documentation and operating procedures.
  • Precise definition of the scope handed to the auditor.
B12To audit

Independent security audit

To do
  • Independent audit of smart contracts and critical components.
  • Review of invariants and attack surfaces.
  • Audit report, remediation plan, fixes and re-test.
04 · Sequencing

Four work packages, a demonstrable output at each stage

Overall dependency: Package 1 → Package 2 → Package 3 → Package 4. Some work can run in parallel once the relevant interfaces and invariants have been stabilised.

Package 1

Core Protocol

B0 – B4

Integrated baseline: clearing engine, portable EVM core, Sei adapter, EVM settlement and Osnias-ID.

Package 2

Infrastructure & Interoperability

B5 – B7

Oracles, ISO 20022, jurisdictional O-POPs and replicable pilot nodes.

Package 3

Integrated Demonstrator

B8 – B10

Reconciliation, security hardening and a reproducible multi-node demonstrator.

Package 4

Security Audit

B11 – B12

Audit readiness, independent audit, remediation and re-test.

After the audit. Once the independent audit and remediation are complete, the next phase will target an institutional pilot in a controlled environment, subject to the regulatory framework and the partners selected.
